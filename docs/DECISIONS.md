## 0. 本轮的两个硬约束（用户明确要求）

1. **工作台以「特定工作区 + 特定 session」为单位**，不允许跨区访问。
2. **针对问题的讲解和实例按需生成**，不随列表一起生成，以节约 token。

下面所有决策都服务于这两条；其余按 PLAN 的 M4/M5 推进。

---

## 1. 作用域：工作台绑定 `(sessionId, workspaceRoot)`

**决定**
- 工作台记录新增 `workspaceRoot`（经 `normalizeWorkspacePath()` 归一化的工作区根）。
- 活跃工作台的索引从 `sessionId → workbenchId` 改为 `sessionId|workspaceRoot → workbenchId`。
- 所有读取/写入路由先解析当前会话**当前生效**的工作区（`workingDirectory.get/ensure`），再用 `sameWorkspaceRoot()` 比对。
- 不匹配时的响应**一律 404**，不告诉调用方“存在但不属于你”，避免泄露其他工作区的存在性：
  - 跨会话：`404 workbench-not-found`「这个决策工作台不属于当前会话。」
  - 同一会话切换目录：`404 workbench-other-workspace`「属于另一个工作区，在这里打不开。」
- 完全没有工作区的会话：`409 no-workspace`。
- `/pending` 写入时带上 `workspaceRoot`；若用户在执行 `/decision` 后切换了目录，轮询会**丢弃**该请求而不是打开旧工作区的工作台。

**为什么**
- `session.header.cwd` 是会话初始目录，用户切换目录后不变；只按 sessionId 绑定会把 A 工作区的工作台带进 B 工作区。
- 同一 session 换目录是最容易被忽略的越界路径，必须用“当前生效目录”判定。

**替代方案**
- 只按 sessionId 绑定：不满足要求 1，否决。
- 按工作台 id 校验“来源文档仍在当前工作区内”：文档可能在工作区内但属于另一个工作区（嵌套），语义更弱，否决。
- 跨区时返回 403 并说明存在：更友好但泄露存在性，否决；改为 404。

**影响**
- 旧版（≤0.2.1）落盘记录没有 `workspaceRoot`，**不再恢复**。本机当前原本就没有历史数据，代价为零；这是有意的安全默认值，而不是静默迁移到 `dirname(source.abs)`（那会把工作台错误地绑到子目录）。

## 2. 讲解与实例：两个独立的按需请求

**决定**
- 新增 `POST /examples`，与既有 `POST /explain` 平级；数据字段拆成 `explanation` / `examples` 两套，状态各自独立（`explanationState`、`examplesState`）。
- **打开某一项不再触发任何模型调用**。面板上出现两张“按需卡片”：
  - 「让助手讲解这一项」→ `/explain`（结论、为什么现在、背景、影响、假设、引用）
  - 「举 2–3 个具体例子」→ `/examples`（如果…就…）
- 枚举提示词去掉 `context`（每项 ≤400 字的“为什么需要决定”），并明确要求「不要输出解释、背景段落或具体实例」。
- 讲解提示词去掉 `scenarios`，并明确要求「不要写具体场景或实例」。
- 旧数据兼容：`normalizeExplanationPayload` 仍解析 `scenarios`；实例卡在 `item.examples` 为空时把它作为只读回退显示（标「来自讲解」），不会因此重新生成。

**为什么**
- 原来打开一项就自动生成解释，用户只是翻列表也会为每一题付费；这是本次要求 2 的直接动机。
- 实例和讲解是两种不同的阅读需求（“这是什么” vs “选了会怎样”），拆开后各自缓存、各自重试，单次上下文也更小。

**替代方案**
- 只把自动生成改成手动按钮、仍合并成一次请求：省得少，且实例往往只需要 2–3 句，会被讲解的长文本挤占预算，否决。
- 保留 `context` 字段：每项最多 400 字 × 30 项的输出成本，而它属于“讲解”范畴，按需生成更合理，否决。

**影响**
- 冷启动成本：从“1 次枚举 + N 次解释”变成“1 次枚举”；浏览 8 项从 9 次调用降到 1 次。
- 单题首次阅读多一次点击；这是用一次点击换 token 的显式取舍。

## 3. 推理模型的 `maxTokens` 预算（实测修正）

**决定**
- 讲解 `maxTokens` 最终取 8000，实例 3000，枚举 16000（保留 0.2.1 的降级重试）。
- 遇到 `finishReason=max-tokens` 且没有文本时，沿用原有错误文案「模型达到输出上限仍未给出答案，请重试。」

**为什么**
- 实测把讲解压到 2500 时，模型把预算耗在推理上、正文为空，报 max-tokens 失败；3000 的实例请求反而 2 秒就返回。
- `maxTokens` 是上限不是计费量，提高上限不会增加实际 token 消耗，只避免“推理吃掉正文”的失败。

**替代方案**
- 只在 UI 上做“重试”提示：治标，否决。
- 按题目长度动态调预算：缺乏可靠信号，暂不做。

## 4. 重复决策：合并但保留别名

**决定**
- `mergeDuplicateItems()` 在枚举落地时运行一次。判定“同一决策”的条件：
  - 标题+问题归一化后完全相同；或
  - 问题相同、标题相似（Dice ≥ 0.5 或互相包含）；或
  - 标题+问题的字符二元组 Dice ≥ 0.82。
- 首个条目为规范项，吸收重复项的更强优先级、缺失的选项/推荐/行号/引用；重复项标题写入 `item.mergedFrom`。
- 面板在列表与详情显示「已合并相似决策 N 项」，不静默丢弃。

**为什么**
- 模型对同一决策点给两个措辞不同的标题很常见，逐题回答两遍是纯浪费。
- 保留 `mergedFrom` 让用户能追溯合并了什么，避免“我的问题怎么不见了”。

**替代方案**
- 完全按标题字符串去重：漏掉 `退款渠道` / `退款渠道（微信）` 这类真实重复，否决。
- 只在 UI 标“可能重复”不合并：用户仍要处理两遍，否决。
- 允许手动合并/拆分：交互成本高、边界多，列为后续。

## 5. 来源变更：廉价探测 + 显式重同步

**决定**
- 每次 `GET /workbench` 只对来源文档做一次 `stat`，用 `size/mtimeMs` 与记录值比较，置 `source.stale`；**不读文件、不调模型**。
- `POST /resync` 才重新读取、重算 hash、用 `findStaleItems()` 检查每条引用的 `quote`/`line`，把失效项标 `item.sourceStale`，并清零/记录 `sourceInvalidCount`。
- 失效**不会**改动任何决定；摘要里追加一句「来源文档在该工作台打开后发生过变化」。

**为什么**
- 轮询是 1 秒级的，读整份文档做 hash 不划算；`stat` 足够发现“被改过”。
- 失效处理必须是显式动作：自动重算会悄悄改变用户看到的内容。

**替代方案**
- 每次轮询重算 hash：更准但每秒钟一次整文件读，否决。
- 变更后自动把工作台标 failed：过度反应，否决。

## 6. 历史工作台：列出来，但默认只读

**决定**
- 新增 `GET /workbenches`，只返回**当前 session + 当前 workspace** 的工作台（按更新时间倒序，最多 12 个）。
- 选择器显示「历史工作台」列表，每项有「查看」（只读）与「继续」（`POST /activate` 后编辑）。
- 只读由**服务端**保证：所有变更路由（`/explain`、`/examples`、`/options`、`/ask`、`/decide`、`/submit`、`/write`、`/resync`）都必须命中当前活跃工作台，否则 `409 read-only`。
- 只读时：隐藏决定区、隐藏提问输入、隐藏“提交摘要”；已缓存的讲解/实例/选择照常显示，但**不允许生成新内容**（生成会写状态）。

**为什么**
- 0.2.1 只能恢复“最新一个”，但存储里留着 16 个；列出来才不至于让用户以为数据丢了。
- 只读放在服务端而不是仅靠 UI 隐藏按钮，避免界面 bug 直接改写历史。

**替代方案**
- 打开历史即激活：语义简单，但用户一次误点就会把“当前工作台”换掉，否决。
- 历史只读但仍允许生成讲解：会写历史记录，与“只读”矛盾，否决。

## 7. 键盘、无障碍、国际化

**决定**
- 键盘：`J/K` 与 `↑/↓` 在可见清单内移动，`Esc` 关闭摘要或返回清单；输入框/文本域内不拦截。**不做自动聚焦**，用户点击面板内任意元素后快捷键生效。
- 无障碍：清单 `role=listbox` + 行 `role=option` + `aria-selected`；筛选项带 `aria-pressed`；通知区 `role=status`；选项沿用 `radiogroup`。
- 国际化：`TabBody` 用 `locale.subscribe()` 订阅语言切换并强制重渲染，`t` 仍按调用时读取当前语言。

**为什么**
- 自动聚焦会把焦点从主会话输入框抢走，风险大于收益；而键盘增强本身是 M5 的打磨项。
- 0.2.1 已知限制里“切语言后不立即重渲染”用一行订阅即可解决，成本低。

**替代方案**
- 在根容器 `autoFocus`：可能打断用户正在输入的对话，否决。

## 8. 版本号与兼容性

**决定**：0.2.1 → **0.3.0**。

**为什么**：行为变化（打开不生成、绑定工作区、新路由、历史只读）对使用者可见，属于 minor 而非 patch；同时不破坏 `/decision` 命令与既有路由语义。

**兼容性说明**
- `/explain`、`/options`、`/ask`、`/decide`、`/preview`、`/submit`、`/write` 路径与请求体保持不变。
- `/workbench` 新增可选 `workbenchId` 查询参数；不传时行为与旧版一致（返回当前工作区的活跃工作台）。
- 旧持久化数据不再恢复（见 §1）。

## 9. 本轮明确未做的事（以及原因）

| 事项 | 原因 |
|---|---|
| M4「决策助手升级为带文件工具的子会话」 | 与“省 token”目标冲突：子会话要重放文件工具与项目规则；当前隔离上下文已能满足逐题讲解/实例。保留为可选升级，不阻塞本轮。 |
| 全屏切换、成本面板、完整键盘走查 | 需要浏览器人工确认；自动聚焦已按 §7 否决，其余留待用户在页面里验收后决定。 |
| 多工作台并发 | 一个 `(session, workspace)` 只保留一个活跃工作台；并发会让“摘要提交回主会话”出现歧义。 |
| 手动合并/拆分决策项 | 交互边界多，先用自动合并 + 可见标注覆盖主要场景。 |
| `docs/decisions/` 自动写入 | 仍保持默认不写，必须显式勾选；本轮只验证了写入路径可用并清理了测试产物。 |
| 自动迁移旧版工作台 | 无可靠字段判断所属工作区；按 §1 的安全默认值放弃恢复。 |

## 12. 0.4.0：结果文件、通知与工作台生命周期

**决定**
- 输入是 spec，输出是结果文件：完成时必定写 `docs/decisions/<日期>-<slug>.md`，不再提供「是否写入」勾选。
- 完成 = 写文件 + 通知主会话 + 删除工作台记录 + 关闭右侧 Tab。结果文件是唯一持久交付物。
- 工作开始时注入一条 `[决策工作台] 工作开始` 消息；完成时注入 `[决策工作台] 工作完成` 消息并带结果路径与统计。两条都要求主会话只回复“收到”、不要读取/修改/执行任何文件，等待用户下一步指令。
- 完成弹层提供「完成后让主会话立即读取结果文件」开关，默认关闭。开关保存在浏览器 `localStorage`；开启时只允许读取，仍不允许开始执行。
- 文件选择器改为 query-driven：空输入不扫描；带 `/` 的查询只扫描对应子树；纯名称查询使用 30 秒缓存索引（最多 4000 文档）；跳过更多生成/依赖目录；单次扫描时间预算 150ms/索引 300ms，最多 60 条结果。为什么：大型项目里空查询全量递归既慢又显示无关文件。替代方案：全量后台索引（内存/新鲜度成本高）、要求 2 个字符（相对路径可能更短）均未采用。
- 删除工作台使用面板内确认弹层，不再使用 `window.confirm`：保持主题与键盘交互一致；弹层展示路径与后果，支持 Esc 取消。
- 开始/完成通知与 `/decision` 命令结果跟随当前 DSH locale：面板把 `locale.getSnapshot().active` 传给 `/start-notice` 与 `/submit`；Host 对缺失值回退 `locale.preference`，再回退 `en`。开始通知从 `startFromDocument` 移到面板打开时，避免 Host 在浏览器派生语言未知时默认中文。命令 handler 没有客户端 locale，因此成功/失败结果和菜单说明使用同一 Host 解析规则（显式设置 → `locale.preference` → `en`）。
- `POST /submit` 改为完成语义；`POST /write` 保留为只写文件、不结束工作台的手动接口。
- 旧版状态为 `submitted` 的工作台保留在存储中用于审计，但不再出现在活跃/历史/可恢复列表里。
- 全新空会话的 `/decision` **不做客户端兜底**：DSH 宿主命令目录要等会话首次历史加载后才可用；客户端同名兜底命令实测仍无法可靠触发（点击运行后页面无反应），继续维护的收益低于成本。最终保留宿主命令的既有行为，并在 README/已知限制中明确“先发送一条消息，等会话有历史后再运行 `/decision`”。

**为什么**
- 用户明确要求：完成后的工作台不应该继续存在；最终结果应该以文档形式交回，而不是把摘要塞进主对话。
- 先写文件再删除记录，保证“工作台消失”不会让决定丢失；文件写入失败时工作台保留可重试。
- 开始/完成都只要求确认，避免主 agent 在用户还在做决定时抢跑实施。
- 自动读取默认关闭，延续“未决/结果不被擅自消费”的安全默认；需要时用户可显式打开。

**替代方案**
- 完成后只标记 `submitted` 并保留列表项：用户明确说“不应该还在”，否决。
- 把完整摘要直接注入主会话、不写文件：上下文成本高、不可追溯，且与“答案是 doc”的要求冲突，否决。
- 使用 `agent.inject()` 静默塞入上下文、不唤醒 agent：没有“确认”动作，用户明确要求可确认，否决。
- 全局 DSH settings 开关：需要引入 schemastery/设置命名空间；当前用完成弹层 + 浏览器本地偏好即可，保留升级空间。

**影响**
- 完成路径多一次文件写；写入失败会阻止删除，工作台保持可重试。
- 通知失败（主会话未运行）不阻止文件保存；界面会提示未通知。
- 通知是普通 user 消息，模型可能不严格遵守“只确认”；没有结构化协议强制。
- 结果路径固定 `docs/decisions/`；不回写 spec，不提供完成后的二次编辑。
- 工作台记录删除后，历史列表无法再打开已完成的缓存；需要回看时看结果文件。

**验证**
- `test/shared.test.js`：开始/完成通知文案、结果文件包装（来源、统计、分组）。
- `test/host-delete.test.js`：`/delete` 的作用域与 active 回退；`/submit` 写结果文件、通知内容、删除记录。
- `test/client-smoke.test.js`：客户端 bundle 的 tab/listener 注册与基础样式 token 回归。
- 页面上的完成弹层、Tab 关闭、自动读取开关仍需人工确认。
