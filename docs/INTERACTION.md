# 决策工作台 · 交互方案

> 版本：v0.2（启动方式改为命令）· 2026-10-19
> 对应计划：[PLAN.md](PLAN.md)
> 形态：`/decision` 命令 + 原生右侧栏 Tab + 独立决策助手会话

---

## 1. 目标

把一份 spec 里的开放决策变成右侧栏里一份可逐题阅读、追问、拍板的清单，拍完把决定摘要交还主会话。

| # | 目标 | 可检验的落点 |
|---|---|---|
| G1 | 一条命令开工 | `/decision` 打开选择器；`/decision <文件名>` 直接开始 |
| G2 | 全量决策项可见 | 首屏列出所有决策项，按必决/建议/可选分组 |
| G3 | 单题可理解 | 每题有结构化解释：背景、后果、实例、出处 |
| G4 | 有选项直接选，没选项能生成 | 来自 spec 的选项带标记；缺失时助手生成 2–4 个并给推荐 |
| G5 | 独立 agent、右侧栏、逐题 | 右侧栏 Tab + 独立决策助手会话，不进入主对话 |
| G6 | 决定可回写、可追溯 | 提交生成结构化摘要回主会话；可选写 `DECISIONS.md` |

### 非目标

- 不替用户自动拍板；未决不当已决。
- 不在用户确认前修改 spec 或项目文件。
- 首版不做多人协作 / 审批流。
- 不接管计划审批与权限审批。

## 2. 设计原则

1. **自然**：用户想的是"把这份 spec 的决策过一遍"，不是"配置一个工作台"。
2. **好理解**：说"这份文档有 8 个需要你拿主意的地方"，不说 agent / session / context。
3. **替用户做决定**：默认只生成列表，解释按需生成；默认提交只回传主会话。
4. **常态安静，罕见才打扰**：未决项常驻低饱和计数；只有拿不准、出处失效、提交失败才醒目。
5. **可撤销**：选择、备注、状态切换都能撤销；关 Tab 不丢进度。
6. **每个动作有落点**：生成有骨架屏与流式结果；失败说明原因并给重试。

## 3. 启动：命令而不是提示词

### 3.1 两种形态

| 命令 | 行为 |
|---|---|
| `/decision` | 打开右侧栏面板，首屏是**文件选择器** |
| `/decision <filename>` | 以该文件为来源直接创建工作台，跳过选择器 |

### 3.2 参数规则

1. 去首尾空白；
2. 支持成对引号：`/decision "docs/spec v2.md"`；
3. 允许前导 `@`：`/decision @docs/spec.md`；
4. 其余整段视为一个文件名（含空格需引号）；
5. 先按相对路径解析，再按 basename 在工作区查找；
6. 重名列出候选并要求相对路径重试；
7. 仅接受文本类文档：`.md .markdown .mdx .txt .rst .adoc .json .yaml .yml .html`。

### 3.3 为什么用命令

- 不依赖用户先写对提示词；
- 命令是确定性的：同一句话每次行为一致，不会"模型这次没懂"；
- 目标明确：命令只负责"打开工作台 / 指定来源"，真正的决策生成由工作台里的独立助手完成；
- 命令可以带文件名，省掉一次选择。

### 3.4 命令结果与失败

- 成功：`正在打开决策工作台：docs/spec.md`（或"工作台已打开，选择一份文档开始"）。
- 失败文案遵循三件事：发生了什么 / 为什么 / 怎么办。
  - `当前会话还没有工作区。先打开一个工作区，再运行 /decision。`
  - `没找到“x”。可以运行 /decision 打开面板选择，或检查文件名。`
  - `找到多个同名文件：a、b。请写相对路径再试一次。`
  - `这个文件不在当前工作区内。`
  - `暂不支持 .pdf 格式，先试试 .md / .txt / .json / .yaml。`

## 4. 文件选择器（`/decision` 首屏）

```
┌──────────────────────────────────────────────┐
│  选择一份文档开始                             │
│  会从当前工作区里找 Markdown / 文本类文档。   │
│  也可以直接用 /decision <文件名> 开始。       │
│  ┌────────────────────────────────────────┐  │
│  │ 搜索文件…                              │  │
│  └────────────────────────────────────────┘  │
│  spec.md                        docs/        │
│  payment-refactor.md            docs/        │
│  decisions/checkout.md          docs/        │
│  README.md                      .            │
│  …                                           │
└──────────────────────────────────────────────┘
```

- 数据来自当前会话工作区；跳过 `node_modules`、`.git`、`dist` 等目录，最多 200 条。
- 按修改时间从新到旧。
- 输入即搜索（150ms 防抖）；点击或回车选中，选中后调用 `/start` 进入工作台。
- 空态：无文档 → `工作区里没有找到可用的文档。`；搜索无结果 → `没有匹配的文件。`
- 加载失败：显示原因 + `重试`。
- 没有工作区：`当前会话还没有工作区。`

## 5. 端到端流程

```mermaid
flowchart TD
  A["/decision 或 /decision <文件名>"] --> B{有参数?}
  B -- 否 --> C[写入 pending pick]
  B -- 是 --> D[解析文件]
  D -->|失败| E[命令返回错误文案]
  D -->|成功| F[写入 pending file]
  C --> G[浏览器监听器轮询 /pending]
  F --> G
  G --> H{模式}
  H -- pick --> I[打开 Tab，显示文件选择器]
  H -- file --> J[调 /start，打开 Tab，进入工作台]
  I --> K[用户选中文档]
  K --> J
  J --> L[决策助手枚举全部决策项 M2]
  L --> M[逐题：看解释 / 问助手 / 选 / 自定义]
  M --> N{全部处理?}
  N -- 否 --> M
  N -- 是 --> O[预览决定摘要]
  O --> P[提交]
  P --> Q[摘要作为带来源标记的用户消息回到主会话]
  Q --> R[主 agent 按决定继续执行]
  O -->|可选| S[写入 DECISIONS.md]
```

## 7. 交互细节

### 7.1 列表

- 分组：必须决定 → 建议决定 → 可选；组内按文档顺序；组可折叠。
- 状态图标（低饱和）：`○` 未看 / `◐` 正在看或有追问 / `✓` 已决定 / `?` 拿不准 / `↷` 稍后。
- 顶部筛选：全部 / 未决 / 已决 / 拿不准 / 必决；筛选与状态持久化。
- 键盘：`↑/↓` 或 `J/K` 移动，`Enter` 进入详情。
- 底部"＋ 漏了一项"：追加一条问题，助手按需补解释与选项。
- 超过 20 项时自动收起"可选"组。

### 7.2 单题详情

进入详情时懒加载：

1. 先渲染题干、出处、优先级、已有选项；
2. 并行请求解释卡与缺失选项；骨架屏 + 流式；
3. 结果缓存，切回不重复请求。

解释卡固定六段：

| 区块 | 内容 | 目的 |
|---|---|---|
| 这个决定在解决什么 | 一句话 + 不决定的后果 | 为什么现在要想 |
| 背景知识 | 术语/机制，1–3 句 | 补齐理解门槛 |
| 实际场景 | "选 A 会发生…；选 B…" | 用户要的例子 |
| 影响面 | 涉及模块/角色/后续步骤 | 判断轻重 |
| 假设与不确定 | 哪些是推断、需核实 | 不把推断当事实 |
| 出处 | spec 章节 + `文件:行` | 可回溯 |

### 7.3 选项

三种来源必须可区分：

| 来源 | 标记 | 行为 |
|---|---|---|
| spec 已给 | `来自 spec` | 直接展示可点选 |
| 助手生成 | `助手补充` | 2–4 个方案 + "保持现状/不做"兜底 |
| 用户自定义 | `自定义` | 选项栈最后一行输入框，选中即生效 |

每个选项卡：方案名（≤12 字）、一句话代价、适用条件、风险（如有）、推荐标记（最多一个且必须带理由）。

无选项：`spec 没有给出备选` + 主按钮"让助手给 2–3 个方案"；生成后推荐项排第一。

### 7.4 问一问

- 每题独立 thread，折叠面板。
- 决策助手只看：本题 + 来源片段 + 项目规则 + 本工作台已做决定；不继承主对话。
- 建议问法：`举个例子` / `选这个的代价是什么` / `为什么不选另一个` / `业界通常怎么做` / `对我们现有代码有什么影响` / `帮我按“改动最小”推荐一个`。
- 回答要求：先结论后依据；项目事实带 `文件:行`；最多 3 次只读检索；不替用户拍板。
- 回填：`用这段理由`（压缩成决定理由）、`把这题改成…`（转成自定义选项，需再确认选中）。
- 追问只留在本题 thread 与工作台数据里。

### 7.5 做出决定

- 点选项卡单选；多选决策项显示复选框并标 `多选`。
- 三出口：
  - **标记为已决定**：保存选择 + 可选理由；没写理由可"让助手帮我写一句"。
  - **拿不准**：保存当前选择（可空）+ 待复核标记，进入"拿不准"筛选；不阻塞提交但提交时二次确认。
  - **稍后**：只记录稍后，不计入已决。
- 自动保存：选择/理由变化 500ms 防抖落盘；关 Tab、刷新、重启不丢。
- 撤销：`⌘/Ctrl+Z` 或详情右上角"撤销上一次决定"，只回退该题。
- 决定后详情不收起，保留阅读位置；列表状态即时更新。

### 7.6 提交

1. 未决 > 0 时提交仍可用，但先确认：`还有 2 项未决，提交后主会话会按“待定”处理。` 拿不准单独列出。
2. 先打开决定摘要预览（只读、可复制、可返回修改）。
3. 确认后：
   - Host 生成摘要并注入主会话；
   - 工作台进入已提交：顶部显示"已交回主会话"，按钮变为"继续追问 / 重新打开 / 关闭"；
   - 勾选"同时写入项目"才写 `docs/decisions/<date>-<slug>.md`。
4. 提交失败：保留全部状态，提示"决定没有丢，重试即可"。

### 7.7 来源变化与失效

- 记录来源 `hash + mtime`；打开期间变化时顶部提示 `spec 已更新，3 项出处可能失效`。
- 按钮：`重新同步`（只重算变化题）/ `忽略`（本次不再提示）。
- 已做决定不自动变；摘要标注"来源已变化"。
- 选项已从 spec 删除：置灰标 `已不在 spec 中`；已选则该题标 `需要复核`。

### 7.8 关闭与重新打开

- 关闭 Tab 不丢状态；重开恢复筛选、选中项、滚动位置。
- 同一会话只允许一个活动工作台；再次 `/decision`：
  - 来源相同：聚焦已有 Tab；
  - 来源不同：询问"替换 / 新建"（旧工作台保留为只读历史）。
- 已提交工作台只读，但"继续追问"可用。

## 8. 上下文策略

| 内容 | 上限 | 说明 |
|---|---|---|
| spec 决策相关片段 | 每题 ≤1.5k 字，整包 ≤6k 字 | 章节 + 决策点前后文 + 表格 |
| 项目规则摘要 | ≤2k 字 | `AGENTS.md` / 项目说明的摘要 |
| 决策项列表 | 全量 | 标题、优先级、出处、已有选项 |
| 本工作台已做决定 | 全量 | 保持一致 |
| 主会话历史 | 0 | 不继承 |

- 初始预算 6–8k tokens；单题解释 ≤1.5k；单次追问 ≤2k（含 ≤3 次只读结果）；整工作台 ≤32k。
- 懒生成顺序：列表 → 打开某题（解释 + 缺失选项）→ 展开完整解释 → 追问按需检索。

### 决策助手权限

- 只读：工作区文件、可选联网检索；
- 禁止：写文件、执行命令、修改 git、改变状态的外部 MCP；
- 每次追问最多 3 次工具调用，结果截断并标来源。

## 9. 决定摘要协议

提交后注入主会话：

```md
<!-- source: decision-workbench:dw_01H... -->
## 决策结果 · 支付重构 spec

- Q1 退款渠道：**微信原路退回**（来自 spec；理由：改动最小）
- Q2 幂等范围：**订单号 + 业务类型**（来自 spec）
- Q3 超时自动退款：**A 自动退款**（助手补充；理由：与现有对账一致）
- Q4 对账口径：**拿不准** ← 需要进一步确认
- Q5 日志级别：**稍后** ← 未决定
- …（完整列表）

补充说明：
- 拿不准：Q4（用户备注：等财务确认口径）
- 未决：Q5
- 来源：spec.md @ <hash>；来源在工作台打开后发生过变化
- 写入项目：docs/decisions/2026-10-19-payment-refactor.md（如勾选）
```

主 agent 约定：

- 已决项按决定执行；
- 拿不准与未决不得自行猜测，需标出并确认；
- 摘要只作为决策记录，不作为新任务指令。

## 10. 状态模型

### 工作台

```
idle → generating → ready → submitting → submitted → reopened
失败：generating 失败 → 错误 + 重试；submitting 失败 → 回 ready 并保留摘要草稿
```

### 决策项

```
unseen ──open──▶ viewing ──decide──▶ decided
                    ├──unsure──▶ unsure
                    └──defer───▶ deferred
任何状态可 reopen；decided / unsure 可撤销。
```

## 11. 键盘 / 无障碍 / 响应式 / 国际化

### 键盘

| 按键 | 动作 |
|---|---|
| `↑ / ↓` 或 `J / K` | 列表移动 |
| `Enter` | 进入详情 / 确认当前选择 |
| `1–9` | 选中第 N 个选项 |
| `E` | 展开/收起完整解释 |
| `Q` | 聚焦"问一问" |
| `⌘/Ctrl + Enter` | 提交 |
| `Esc` | 详情返回列表 / 关闭浮层 |
| `⌘/Ctrl + Z` | 撤销上一次决定 |

### 无障碍

- 列表 `listbox` + `aria-activedescendant`；
- 状态变化 `aria-live="polite"`；
- 选项 `radiogroup`，多选 `group` + `checkbox`；
- 焦点环可见；流式解释不抢焦点；尊重 `prefers-reduced-motion`。

### 响应式

- 正常：左列表 220–260px + 右详情，列表可折叠；
- <520px：列表变顶部分段控件；
- <768px：自动全屏；底部提交条常驻；

### 国际化

- 全部文案走 locale 命名空间（中英）；

## 12. 空、加载、错误与边界

| 场景 | 设计 |
|---|---|
| 未找到决策项 | `这份文档里没有找到需要你拍板的问题` + `让助手再找一遍` + `手动加一项` |
| 列表生成中 | 骨架 3 行 + 文案 + 取消 |
| 解释失败 | 内联错误 + 原因 + 重试；不影响选择 |
| 助手不可用 | `决策助手暂时不可用`；决定仍可保存 |
| 工作区缺失 | 选择器显示 `当前会话还没有工作区。` |
| 文件被删/改 | 顶部提示 + `重新同步`；已决内容不丢 |
| 存储写失败 | 内存继续可用；提示"进度可能无法跨重启保留" |
| 决策项 > 50 | 按章节分组，默认只展开前两组 |
| 重复决策 | `可能重复` 角标，可合并 |
| 主会话不可用 | 摘要保存；提示"稍后可重新打开该会话发送" |

## 13. 文案规范

- 标题：`决策工作台`。
- 进度：`已决 5 · 未决 2`。
- 推荐：`[推荐] 与现有对账流程一致`（必须带理由）。
- 按钮：`标记为已决定`、`拿不准`、`稍后`、`提交`、`预览决定摘要`。
- 错误三件事：例如 `解释没生成出来。这次请求超时了。可以重试，或者先按现有选项决定。`
- 提交确认：`还有 2 项未决。提交后主会话会把它们标成“待定”，不会自己猜。`

## 14. 验收与走查

### 验收标准

- `/decision` 1 秒内打开右侧栏，首屏是文件选择器且能列出工作区文档。
- `/decision docs/spec.md` 跳过选择器直接进入工作台。
- 打开任一题 3 秒内出现解释首段（流式）。
- 有选项标"来自 spec"；无选项可生成 2–4 个方案并给推荐。
- 每个选项有且仅有一个推荐，推荐带理由；每题至少一个出处。
- 关闭/刷新/重启后进度不丢（M3 起）。
- 提交后主会话收到结构化摘要；未决与拿不准不被猜成已决。
- 未点"写入项目"前工作区无文件被修改。
- 键盘可完成"浏览 → 选择 → 提交"全流程。

### 走查 A：有备选

1. `/decision docs/payment.md`。
2. 列表 8 项（3 必决 / 3 建议 / 2 可选）。
3. 打开 Q1：选项标"来自 spec"，推荐项带理由。
4. 问"选 B 的代价"，回答带出处；点"用这段理由"。
5. 决定 5 项，2 项拿不准，1 项稍后。
6. 提交：确认列出未决/拿不准；摘要预览正确。
7. 主会话收到摘要；主 agent 未猜未决项。

### 走查 B：无备选

1. `/decision` → 选择器选中只有"待定：缓存方案"的 spec。
2. 该题显示"spec 没有给出备选"。
3. 点"让助手给方案" → 3 个方案 + 保持现状，推荐项第一。
4. 追问"业界通常怎么做"，回答带来源。
5. 选自定义方案，标记已决定，提交。

### 走查 C：来源变化

1. 打开工作台后外部编辑 spec，删除一个已选备选。
2. 顶部出现"spec 已更新"。
3. 点"重新同步"：该题标"需要复核"。
4. 重新选择后提交，摘要标注"来源已变化"。
