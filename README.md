# dsh-decision-workbench

DeepSeek Harness 的**决策工作台**：通过 `/decision` 打开右侧栏面板，把一份 spec 里的开放决策拆成逐题选择，随时向隔离的决策助手追问，最后把决定写成结果文件并通知主会话。

> **状态：0.4.1（M1 + M2 + M3 完整；M4/M5 部分完成）**
> 已在 DSH Web 0.2.1-rc.2（`desktop` profile）实测：命令链路、决策枚举、按需讲解与实例、无选项补方案、逐题追问、选择与摘要预览、来源变更检测与重同步、历史工作台只读浏览与删除、跨会话/跨工作区拒绝。0.4.x 的完成流程已通过 Host 路由测试；页面上的完成弹层、Tab 关闭与通知观感待人工确认。
> **工作台绑定「会话 + 工作区」**：切换工作目录后看不到、也改不了原来的工作台；另一个会话同样看不到。
> **讲解与实例都按需生成**：打开某一项不会产生任何模型调用，点按钮才生成。
> 计划见 [docs/PLAN.md](docs/PLAN.md)，交互方案见 [docs/INTERACTION.md](docs/INTERACTION.md)，本轮自主拍板的开发决策见 [docs/DECISIONS.md](docs/DECISIONS.md)，示例文档见 [example/](example/)。

## 它解决什么

一份 spec 里通常散落着若干"需要人拍板"的点：有备选方案的、只有问题没有方案的、影响开工的、可以后补的。工作台把它们收进右侧栏：

1. `/decision` 或 `/decision <文件名>` 启动；
2. 自动通读文档，列出全部决策项（必决 / 建议 / 可选）；
3. **只在点按钮时**才生成这一题的讲解（结论、为什么现在、背景、影响、假设、引用）；
4. 想要具体场景时，再点「举 2–3 个具体例子」，生成「如果…就…」；
5. spec 有选项就直接选；没有就让助手补 2–4 个方案并给推荐；
6. 对任意一题追问，回答只看文档与本工作台，不污染主对话；
7. 逐题标记"已决定 / 拿不准 / 稍后"，预览摘要后完成工作台；结果写入 `docs/decisions/<日期>-<slug>.md`，主会话收到“工作完成”的通知并等待你的下一步指令。

未决和拿不准会在结果文件里显式保留，主 agent 不会被暗示去猜。完成后的工作台不会保留，结果文件就是交付物。

## 用法

```
/decision                  打开右侧栏，选择一份文档开始（若有上次工作台可直接继续）
/decision <文件名>         直接以该文件开始（相对工作区路径，可加引号）
```

示例：

```
/decision docs/payment-refactor.md
/decision "docs/spec v2.md"
/decision @spec.md
```

文件名解析规则：

- 先按相对路径找，再按 basename 在工作区里找；
- 重名会列出候选，要求写相对路径；
- 只接受 `.md .markdown .mdx .txt .rst .adoc .json .yaml .yml .html`；
- 文件必须在当前会话工作区内；
- 面板只读取输入文档，不修改它；完成时会生成 `docs/decisions/<日期>-<slug>.md` 结果文件。
- **`/decision` 只能在已经有历史的会话里运行。** 全新空会话中，DSH 还没有加载宿主命令目录，命令会被静默拒绝；先发送一条消息，再运行 `/decision`。这是 DSH 的命令发现限制，插件侧不做兜底。

## 面板怎么用

布局：面板宽度 ≥520px 时是双栏——左侧决策清单（固定约 180–250px），右侧是当前题的解释、选项、决定区和问一问，底部是完成条；更窄时点开一题进入详情、左上角“返回清单”。

| 区域 | 作用 |
|---|---|
| 文件选择器 | 输入相对路径或文件名搜索（空输入不扫描项目）；**输入框保持焦点**，`↑/↓` 选择候选、`Enter` 打开。只有候选列表实际变化时才清除高亮。顶部显示"继续上次的工作台"，下方列出**历史工作台**（只读查看 / 继续编辑 / 删除）。删除使用面板内确认弹层 |
| 决策清单 | 按优先级分组，可筛选全部 / 必决 / 未完成 / 已决定；显示进度与必决剩余；相似决策显示"已合并 N 项" |
| 单题详情 | 题干、出处、讲解卡、实例卡、选项、自定义方案、理由、三态按钮 |
| 讲解卡 | 默认不生成；点「让助手讲解这一项」才生成结论/为什么现在/背景/影响/假设/引用 |
| 实例卡 | 默认不生成；点「举 2–3 个具体例子」才生成「如果…就…」场景 |
| 选项 | 标记"来自 spec / 助手补充"；推荐项带理由；无选项时可让助手补 |
| 问一问 | 每题独立 thread；回答带 `文件:行` 出处；建议问法一键发送 |
| 摘要与完成 | 预览完整摘要、复制；完成后写入结果文件、通知主会话并关闭工作台。可勾选让主 agent 立即读取结果并开始执行（默认只通知路径并等待） |

进度、选择、理由、追问线程、已生成的讲解与实例都会自动保存；关闭 Tab、刷新页面、重启 Harness 后再次 `/decision` 可继续未完成的工作台。完成后的工作台会被删除，只有结果文件保留。

来源文档被外部修改时，顶部提示「来源文档已更新」，可点「重新同步」重算出处；失效的项标「出处可能失效」，已做的决定不会被自动改动。

历史工作台默认只读：可以查看已缓存的讲解、实例与决定；点「继续这个工作台」才能修改（服务端也会拒绝在非活跃工作台上写入）。历史工作台可直接删除（面板内确认弹层）；删除活跃工作台后会自动切到最近一个剩余工作台。完成（`submitted`）的旧工作台不再出现在历史或“继续上次”列表中。

## 设计要点

- **命令优先**：启动不依赖提示词。命令在 Host 侧解析文件，浏览器半通过 pending 轮询打开 Tab。
- **作用域封闭**：工作台属于创建它的「会话 + 工作区」。所有路由先解析当前生效目录再比对，跨区一律 404；轮询 `/pending` 也会在目录切换后作废旧请求。
- **隔离的决策助手**：每次生成或追问都是独立、只读的模型调用，提示词只包含文档片段、本题和本工作台已做决定，不继承主会话历史。
- **列表先到、讲解与实例按需**：先出全部决策项；讲解与实例各自一个按钮、各自缓存；不点就不花 token。
- **未决不猜**：结果文件把"已决定 / 拿不准 / 稍后 / 未处理"分开，并明确要求主 agent 不自行补答。
- **输入只读、输出必写**：工作台不改 spec；完成时必定写 `docs/decisions/` 结果文件，这是唯一交付物。
- **完成即消失**：结果文件写成功后删除工作台记录并关闭 Tab；主会话只收到路径与“等待指令”的通知。
- **跟随界面语言**：开始/完成通知、`/decision` 的命令结果与菜单说明都按当前 DSH locale（`zh` / `en`）生成；开始通知在面板打开、拿到浏览器 active locale 后发送，完成通知在 `/submit` 中携带 locale；命令结果使用 Host locale 设置，缺失时回退英文。
- **来源可核对**：来源被改过只提示、不自动改写决定；重同步才更新 hash 与失效标记。
- **可恢复（仅未完成）**：工作台、决策项、讲解、实例、追问、选择写入 `$DSH_HOME/storages/dsh-decision-workbench/workbenches.json`（保留最近 16 个），历史可按会话+工作区浏览；完成的工作台在上述文件中被删除。

## 实现

```
src/index.js     Host：/decision 命令、JSON 路由、工作区作用域、模型调用、结果文件、通知、持久化
src/client.js    Client：右侧栏 Tab 类型、文件选择器、清单/详情、按需讲解与实例、问答、完成流程
src/shared.js    纯函数：参数解析、JSON 提取与归一化、提示词、重复合并、失效检测、摘要、通知文案、结果文件、slug
docs/PLAN.md     项目计划
docs/INTERACTION.md  交互方案
docs/DECISIONS.md    本轮自主拍板的开发决策记录
example/         两份待测文档（有选项 / 无选项）
test/            node --test 单测（37 项）
```

Host 侧使用 `ctx.get('llm').stream()` 调用当前 profile 的默认模型（`agentDefaultModel`），只消费文本 delta；`ctx.get('agents')` 用于把开始/完成通知 `followup` 回主会话；`ctx.get('webServer')` 提供 loopback + 同源校验的 JSON 路由；`ctx.get('workingDirectory')` 决定当前生效工作区。

### 路由

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/dsh-decision-workbench/pending?sessionId=` | 取待打开请求（pick / workbench；目录切换后作废） |
| POST | `/dsh-decision-workbench/pending/ack` | 面板处理完后清除请求 |
| GET | `/dsh-decision-workbench/files?sessionId=&query=` | 按相对路径/文件名搜索；空 query 返回空；带时间/结果预算 |
| POST | `/dsh-decision-workbench/start` | `{ sessionId, path, restart? }` 创建并开始枚举 |
| POST | `/dsh-decision-workbench/start-notice` | `{ sessionId, workbenchId, locale? }` 按当前语言发送开始通知（幂等） |
| GET | `/dsh-decision-workbench/workbench?sessionId=&workbenchId=` | 取当前工作台（可指定 id 浏览历史，含来源状态） |
| GET | `/dsh-decision-workbench/workbenches?sessionId=` | 列出本会话 + 本工作区的历史工作台 |
| POST | `/dsh-decision-workbench/activate` | 把某个历史工作台设为活跃（之后可编辑） |
| POST | `/dsh-decision-workbench/delete` | 删除本会话 + 本工作区的某个工作台（活跃项删除后回退到最近一个） |
| POST | `/dsh-decision-workbench/item` | 记录某题被打开（不触发生成） |
| POST | `/dsh-decision-workbench/explain` | 按需生成单题讲解（`force` 重试） |
| POST | `/dsh-decision-workbench/examples` | 按需生成 2–3 个具体例子 |
| POST | `/dsh-decision-workbench/options` | 无选项时补 2–4 个方案 |
| POST | `/dsh-decision-workbench/ask` | 针对单题追问（立即返回，轮询收敛） |
| POST | `/dsh-decision-workbench/decide` | 三态 / 清除决定 |
| POST | `/dsh-decision-workbench/preview` | 生成摘要文本与统计 |
| POST | `/dsh-decision-workbench/submit` | 写结果文件、通知主会话、删除工作台（`autoRead` / `locale` 可选） |
| POST | `/dsh-decision-workbench/write` | 只写结果文件、不结束工作台（手动接口） |
| POST | `/dsh-decision-workbench/resync` | 重算来源 hash 并标记失效引用 |

所有路由 loopback + 同源校验；工作台路由额外校验「会话 + 当前生效工作区」，跨区返回 404。除 `/delete` 外，变更路由只接受当前活跃工作台（历史工作台返回 `409 read-only`）。模型调用 180 秒超时。

## 安装

本机约定（源码 clone + link）：

```powershell
git clone <repo> F:\dsh-plugin\dsh-decision-workbench
# 在目标 profile 目录：
pnpm add link:F:\dsh-plugin\dsh-decision-workbench
```

或用插件管理器安装本地目录：

```sh
dsh plugin --profile desktop add link:F:/dsh-plugin/dsh-decision-workbench
```

安装后重启 `dsh web`（或禁用/启用一次插件行）并刷新页面。要求 DSH Web 0.2.x，Node.js ≥ 22；零运行时依赖、无构建步骤。

## 第一次使用

- 安装或更新插件后，先刷新一次网页，让浏览器半加载新的 client bundle；Host 半的改动需要禁用再启用插件行（或重启 `dsh web`）。
- `/decision` 执行后会立即出现一条“决策工作台已打开”的命令结果，右侧栏应同时展开并显示文件选择器。若右侧栏原本处于收起状态，也可以点会话右上角的展开按钮找回。
- **会话必须是已有历史的**：全新空会话里 `/decision` 不会执行；先发送一条消息，再运行命令。
- 选择文件开始后，主会话会收到“工作开始”的消息并要求只确认；完成后会收到“工作完成”+结果文件路径。默认不读取结果、等待你的下一步指令；勾选“完成后立即交给主 agent 执行”后，主 agent 会直接读取结果并开始执行「已决定」的项，不再先回复确认。
- 如果 `/` 菜单里没有 `decision`，到设置 → 插件确认 `dsh-decision-workbench` 已启用。

## 已知限制

- 决策助手是隔离的模型上下文，不是带文件工具的独立 DSH 子会话；文档全文（最多 60k 字）以片段形式内联给模型，超长文档会截断。升级为子会话仍是 M4 的可选项（见 [docs/DECISIONS.md](docs/DECISIONS.md) §9）。
- 开始/完成通知是一条普通用户消息（带 `[决策工作台]` 前缀），不是结构化协议消息；模型可能不严格遵守“只确认”，需要用户监督。
- 工作台严格绑定创建时的会话与工作区：换目录后原工作台“看不见”，切回目录才恢复；旧版（≤0.2.1）没有工作区字段的持久化记录不再恢复。
- 历史工作台默认只读，只显示已缓存的讲解/实例；要生成新内容必须先「继续这个工作台」。完成后的工作台会被删除，历史里看不到；结果文件是唯一持久结果。
- 一个会话在一个工作区内只保留一个活跃工作台；历史最多列出 12 个（存储保留 16 个），可在选择器里删除。
- 文件搜索不是全量索引：空查询不扫描；名称搜索使用 30 秒缓存索引（最多 4000 个文档），相对路径只扫描对应子树；跳过 `node_modules`、`.git`、`dist`、`build`、`target` 等生成/依赖目录，最多返回 60 条。深层文件请用更具体的相对路径。
- 键盘快捷键需要面板内有焦点（不做自动聚焦，避免抢走主会话输入焦点）。
- `/decision` 需要会话已有历史：全新空会话中 DSH 尚未加载宿主命令目录，命令不会执行，也不会弹出提示；先发送一条消息，再运行。
- 结果文件固定写到 `docs/decisions/<日期>-<slug>.md`，不会回写 spec，也不会生成其他格式；工作台完成后不能二次编辑。
- “立即交给主 agent 执行”会要求模型读取结果后直接开工；模型仍可能不遵守或执行偏差，需要用户监督。
- 面板视觉、真实点击流程与语言切换观感仍需在页面里人工确认；自动化验证覆盖纯函数、客户端冒烟与 Host 路由（含跨区拒绝）。
- 模型输出预算随题目复杂度波动；讲解/实例在推理型模型上偶发 max-tokens 失败，界面提供重试。
