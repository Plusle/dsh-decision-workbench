# example/ · 待测文档

这两份文档用于手工验证决策工作台的两种核心场景。内容为虚构业务，只服务于测试。

| 文件 | 场景 | 期望工作台行为 |
|---|---|---|
| `payment-refactor-with-options.md` | **有备选**：8 个决策点，每个都带 2–3 个候选方案 | 选项标"来自 spec"；推荐项能对应文中的"倾向"；列表按必决 / 建议 / 可选分组 |
| `payment-refactor-open-questions.md` | **无备选**：8 个开放问题，只有问题与背景，没有候选方案 | 打开单题时显示"spec 没有给出备选"，由决策助手补充 2–4 个方案并给推荐 |

## 怎么用

工作台只读取**当前会话工作区**里的文档。两种用法：

1. 新开一个会话，把工作区指向本插件工程目录（`F:\dsh-plugin\dsh-decision-workbench`），然后：
   - `/decision` → 在文件选择器里选 `example/payment-refactor-with-options.md`；
   - 或直接 `/decision example/payment-refactor-with-options.md`。
2. 或把这两份文档复制到任意测试工作区，再执行上面的命令。

## 预期结果（0.2.0 已实测）

### 有备选文档

- 列表 8 项，3 必决 / 3 建议 / 2 可选；每题至少一个出处（`文件:行`）。
- 选项全部标"来自 spec"；推荐项能对应文中的"倾向"（如决策 1 推荐 A）。
- 打开单题会自动生成解释卡（结论、为什么现在、背景、场景、影响、假设、引用）。
- 对单题追问"选这个的代价是什么"，回答带 `文件:行` 出处。

### 无备选文档

- 列表 8 项；每题选项为空，显示"文档没有为这一项给出备选方案"。
- 点"让助手补充 2–3 个方案"后出现 2–4 个方案与一个带理由的推荐。
- 优先级由工作台判断（实测 4 必决 / 4 建议）。

### 通用

- 已决定 / 拿不准 / 稍后 / 清除本题决定均可记录，理由写入摘要。
- "预览并提交摘要"生成完整摘要，未决与拿不准显式保留；提交后回到主会话。
- 可勾选同时写入 `docs/decisions/<日期>-<标题>.md`。
- 关闭 Tab、刷新页面、重启 Harness 后再次 `/decision`，可从"继续上次的工作台"恢复。
